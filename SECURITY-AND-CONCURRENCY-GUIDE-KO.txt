FEED FLOW 보안·동시성 적용 안내

1. 비밀번호 재설정
- 회원정보가 일치해야 6자리 인증번호가 생성됩니다.
- 인증번호 원문은 DB에 저장하지 않으며 5분 후 만료됩니다.
- 30초 안에는 다시 발급할 수 없고 5회 틀리면 폐기됩니다.
- 회원 존재 여부는 인증번호 요청 API 응답으로 알려주지 않습니다.

로컬 시연:
- application.properties 기본값은 Console 발송입니다.
- STS Console의 '[FEED FLOW 개발용 비밀번호 인증번호]' 줄을 확인합니다.

운영 배포:
- FEEDFLOW_RECOVERY_CONSOLE_ENABLED=false
- ConsoleRecoveryCodeSender 대신 이메일 또는 SMS RecoveryCodeSender를 구현합니다.
- 인증번호를 브라우저 응답, Git, 로그 수집 서비스에 그대로 노출하면 안 됩니다.

2. 재고 동시성
- 주문 시 사용 가능한 LOT을 유통기한 순으로 조회하면서 DB 쓰기 잠금을 획득합니다.
- 다른 주문은 첫 주문의 재고 차감이 끝난 뒤 최신 재고로 다시 판단합니다.
- 주문 취소 시에도 주문과 배정 LOT을 잠근 뒤 한 번만 복원합니다.

3. 결제 멱등성
- 같은 주문의 콜백·웹훅·복구 요청은 주문 쓰기 잠금으로 직렬화됩니다.
- 이미 완료된 동일 imp_uid 요청은 성공 결과를 그대로 반환합니다.
- 다른 주문에서 사용 중인 imp_uid는 거부합니다.
- H2 DB에도 결제번호 고유 인덱스가 적용됩니다.

4. 오류 정보 보호
- 404, 500, 기타 오류에 Feed Flow 공통 화면을 사용합니다.
- 기본 오류 화면에는 내부 예외 메시지와 스택트레이스를 표시하지 않습니다.
- API의 업무 오류는 사용자가 조치할 수 있는 안전한 문장만 반환합니다.
