FEED FLOW PortOne 결제 연동 안내
================================

1. 보안 원칙
------------

- 실제 고객사 식별코드, REST API Key, REST API Secret, 채널 키는 소스코드에 적지 않습니다.
- 키는 STS의 Run Configuration 환경변수에만 등록합니다.
- Git, ZIP, 채팅, 화면 캡처에 실제 키를 포함하지 않습니다.
- 키가 외부에 노출되었다면 PortOne 콘솔에서 즉시 재발급하고 기존 키를 폐기합니다.
- 브라우저에는 고객사 식별코드와 채널 키만 전달됩니다.
- REST API Secret은 서버에서만 사용하며 HTML 또는 JavaScript로 전송하지 않습니다.


2. PortOne 콘솔에서 준비할 값
----------------------------

다음 값을 PortOne 콘솔에서 확인하거나 발급합니다.

- 고객사 식별코드
- REST API Key
- REST API Secret
- 일반 신용카드용 채널 키
- 카카오페이용 채널 키
- 가상계좌용 채널 키

카카오페이 테스트 CID 같은 PG사 값은 PortOne 콘솔에서 결제 채널을 등록할 때 사용합니다.
STS 환경변수에는 PortOne이 생성한 채널 키를 입력해야 합니다.


3. STS 환경변수 등록
-------------------

STS에서 아래 순서로 이동합니다.

Run
→ Run Configurations
→ Spring Boot App
→ finalProject
→ Environment
→ Add

각 항목은 Name과 Value를 한 개씩 등록합니다.

Name: PORTONE_CUSTOMER_CODE
Value: <PortOne 고객사 식별코드>

Name: PORTONE_API_KEY
Value: <PortOne REST API Key>

Name: PORTONE_API_SECRET
Value: <PortOne REST API Secret>

Name: PORTONE_CARD_CHANNEL_KEY
Value: <일반 신용카드 채널 키>

Name: PORTONE_KAKAO_CHANNEL_KEY
Value: <카카오페이 채널 키>

Name: PORTONE_VBANK_CHANNEL_KEY
Value: <가상계좌 채널 키>

환경변수 창 아래에서는 다음 옵션을 선택합니다.

Append environment to native environment

등록 후 Apply → Run을 누릅니다.


4. 설정 확인
------------

서버를 다시 실행한 뒤 다음 주소를 확인합니다.

http://localhost:8080/api/payments/config

응답에서 enabled가 true이고 각 결제수단의 available이 true이면 해당 채널이 준비된 상태입니다.
키 원문은 이 API 응답에 포함되면 안 됩니다.


5. 결제 테스트 순서
------------------

1) 일반 회원으로 로그인합니다.
2) 상품을 장바구니에 담습니다.
3) 장바구니에서 주문하기를 누릅니다.
4) 주문자와 배송지 정보를 확인합니다.
5) 카카오페이, 일반 신용카드, 무통장입금 중 하나를 선택합니다.
6) 결제하기를 누릅니다.
7) PortOne 테스트 결제창에서 테스트 결제를 진행합니다.
8) 마이페이지 주문 내역에서 결제 상태를 확인합니다.

실제 운영 결제 전에는 PortOne과 각 PG사의 가맹점 심사 및 운영 채널 설정이 필요합니다.


6. 결제 처리 구조
----------------

- 브라우저는 PortOne SDK로 결제창을 엽니다.
- 결제창이 반환한 거래 식별자를 Spring Boot 서버로 전달합니다.
- Spring Boot 서버가 PortOne REST API로 실제 결제 금액과 상태를 다시 조회합니다.
- 서버에서 주문 금액과 결제 금액이 일치할 때만 주문을 결제 완료로 변경합니다.
- 브라우저 응답만 믿고 결제 완료로 처리하지 않습니다.


7. 무통장입금 안내
-----------------

현재 무통장입금은 고정 계좌번호를 화면에 적는 방식이 아니라 PortOne 가상계좌 방식입니다.
입금 전에는 주문이 결제대기 상태이며, 입금 확인 후 결제완료 상태로 변경되어야 합니다.
운영 환경에서는 PortOne 웹훅 주소를 외부 HTTPS 주소로 등록해야 합니다.

마이페이지 버튼:

- 입금 확인: PortOne 서버에서 해당 주문번호를 다시 조회합니다.
- 입금 전 주문취소: 발급된 미입금 가상계좌를 PortOne에서 취소한 뒤 주문과 LOT 재고를 복원합니다.
- 입금 완료: 웹훅 또는 입금 확인을 통해 PortOne의 paid 상태가 검증된 주문에 표시됩니다.

localhost는 PortOne 웹훅이 도착하지 않으므로 테스트 입금 후에는
마이페이지에서 '입금 확인'을 눌러 상태를 갱신할 수 있습니다.

vbank는 결제대행사 이름이 아니라 가상계좌 결제수단 코드입니다.
PortOne 채널 목록에서 vbank라는 회사를 찾지 말고 가상계좌를 지원하는 PG사를 등록합니다.

개발 테스트 권장 순서:

1) PortOne 콘솔의 결제 연동 → 채널 관리로 이동합니다.
2) 테스트 모드에서 NHN KCP 채널을 추가합니다.
3) 생성된 채널 키를 복사합니다.
4) STS 환경변수 PORTONE_VBANK_CHANNEL_KEY의 값으로 등록합니다.
5) 서버를 완전히 재실행합니다.
6) 홈페이지에서 무통장입금을 선택하면 같은 채널 키와 pay_method=vbank로 요청됩니다.

실제 운영에서는 NHN KCP, KG이니시스, 토스페이먼츠 등 가상계좌를 지원하는 PG사와
별도의 가상계좌 계약 및 심사를 완료한 채널을 사용해야 합니다.

웹훅 주소:

https://운영도메인/api/payments/portone/webhook

localhost 주소는 PortOne 서버가 접근할 수 없으므로 입금완료 웹훅 테스트에는
외부에서 접근 가능한 HTTPS 주소가 필요합니다.


8. 자주 발생하는 문제
---------------------

[카카오페이 테스트에서 비밀번호 인증 안내가 표시됨]
- "실제 결제에서는 카카오페이 비밀번호 인증 단계가 추가됩니다"라는 화면은 테스트 모드 안내입니다.
- 이 문구만으로 결제 실패를 의미하지 않습니다.
- 휴대폰 인증 후 브라우저 결과는 imp_uid를 사용한 서버의 PortOne 결제 조회 결과로 확정합니다.
- 휴대폰은 성공인데 웹사이트가 실패하면 Spring Boot Console의 "포트원 결제 조회" 오류를 확인합니다.

[결제 수단을 사용할 수 없다는 메시지]
- 해당 채널 키 환경변수가 비어 있는지 확인합니다.
- Run Configuration을 수정한 뒤 서버를 완전히 다시 실행합니다.
- PortOne 콘솔에서 채널이 테스트 모드로 정상 등록됐는지 확인합니다.

[결제창이 열리지 않음]
- 브라우저 팝업 차단 여부를 확인합니다.
- 개발자 도구 Console의 오류를 확인합니다.
- PortOne SDK 주소에 인터넷으로 접근 가능한지 확인합니다.

[결제 후 주문이 완료되지 않음]
- Spring Boot Console의 서버 검증 오류를 확인합니다.
- PortOne 거래 내역의 금액과 주문 금액이 같은지 확인합니다.
- REST API Key와 Secret이 올바른 프로젝트의 값인지 확인합니다.
- 휴대폰에서 결제가 완료됐다면 같은 주문을 다시 결제하지 말고 마이페이지의 '결제상태 확인'을 누릅니다.
- 기존 H2에서 PORTONE 값을 거부했던 프로젝트는 최신 수정본을 실행하면 시작 시 컬럼이 자동 보정됩니다.

[운영 서버에서 콜백 또는 웹훅이 오지 않음]
- localhost는 외부 서비스에서 접근할 수 없습니다.
- 외부에서 접근 가능한 HTTPS 도메인이 필요합니다.
- 방화벽, 프록시, SSL 인증서, 웹훅 URL을 확인합니다.


9. ZIP에 포함하지 않는 항목
-------------------------

- 실제 결제 키
- data 폴더와 H2 로컬 DB
- build 폴더
- .gradle 캐시
- 테스트용 JAR 모음

Import용 ZIP에는 소스, Gradle Wrapper, STS 프로젝트 설정, 빈 환경변수 참조만 포함합니다.
